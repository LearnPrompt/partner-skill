# Partner v1.5 双宿主完整验收

这份文档同时服务两个阶段：Claude Code 对本轮代码做独立静态验收，以及随后由一个完全不了解 Partner 的用户在全新 session 里走完整端到端验收。

## 验收对象

- 仓库：`https://github.com/LearnPrompt/partner-skill`
- 分支：`feat/v1.5-dual-host`
- 本轮基线：`a1cef2e`
- 候选版本：验收时的 `origin/feat/v1.5-dual-host`
- 对比命令：`git diff a1cef2e..origin/feat/v1.5-dual-host`
- 本轮范围：小白安装 UI、模型发现、模型对应 effort、Haiku、双宿主配置增量合并、安装后自动验证、文档与测试。

合并 `main`、发布 tag、生产部署都不在本验收范围内。

## A. Claude Code 独立代码验收

Claude Code 必须从原始任务和本文件开始，不得只看 Codex 的总结。使用 plan/read-only 权限，不修改文件，不 commit，不 push。

### 必读文件

1. `SKILL.md`
2. `references/setup.md`
3. `references/codex-driven.md`
4. `references/claude-driven.md`
5. `references/tryout.md`
6. `scripts/partner-setup.py`
7. `scripts/partner-setup-ui.py`
8. `tests/test_partner_setup.py`
9. `tests/test_partner_setup_ui.py`
10. `README.md` 与 `README.en.md`

### 二元验收门

| 门 | PASS 条件 |
|---|---|
| 小白入口 | 有浏览器时不通过聊天逐项追问；打开 localhost UI；高级 scope/Git/routing/smoke 选择不暴露给小白。 |
| 写入安全 | UI 固定当前项目、`.git/info/exclude`、无常驻路由块、先预览后确认；用户文件不被覆盖。 |
| 模型真值 | Codex 模型及每模型 effort 来自 CLI `model/list`；Claude 别名和 effort 来自 `claude --help`；Haiku 可见；`[1m]`/`1M` 不生成重复项。 |
| 强度约束 | Claude 与 Codex 不共用一套静态 effort；切换 backend/model 后只显示被该选择支持的值；服务端拒绝伪造组合。 |
| 双宿主 | 第二宿主只新增自己的 namespace，另一宿主字节保持不变；两边共用同一 `.partner/config.toml`。 |
| 自动验证 | Codex 角色走 delegate dry-run；Claude 角色走无工具、无 Chrome、无 session 持久化的新 CLI session；只有真实成功才写 `verified=true`。 |
| 失败诚实 | 自动检查失败时配置写入状态和检查状态分开显示；失败角色保持 `verified=false`，不换模型、不伪造 PASS。 |
| 文档一致 | `SKILL.md`、中英文 README、`references/setup.md` 与实际 UI/engine 一致。 |
| 回归 | `python3 -m unittest discover -s tests`、`bash scripts/check-skill-repo.sh .`、`git diff --check` 全部通过。 |

### Claude Code 输出格式

```text
verdict: PASS | FAIL
blocking_findings:
- <none 或 P0/P1，带 file:line 和复现依据>
non_blocking_findings:
- <none 或 P2/P3>
commands_run:
- <命令 + 结果>
e2e_ready: yes | no
reason: <一句话>
```

没有执行过的检查必须明确写 `not run`。测试通过不能替代 diff review。

## B. 完全新用户的 fresh-session E2E

### 测试原则

- 用户假设：不知道 Partner 的角色、配置文件、CLI 参数和命令，只会发送下面给出的自然语言。
- Agent 不得要求用户在聊天中逐项回答模型、scope、Git、routing 或 smoke 问题；这些由 UI 完成。
- 使用一个新的临时 Git 仓库，不在 LearnPrompt 或其他真实项目做安装验收。
- 使用 feature branch 链接，不能误装 `main`。
- 两个宿主都必须真实运行；仅生成配置、仅 dry-run 或只看 `verified=true` 都不算完整接力。
- 安装后若宿主需要新 session 才能发现 skill，Agent 必须明确提示并给出下一句原样可发送的话；这是可接受的单次激活边界。

### 0. 干净环境

由验收 Agent 完成并报告证据：

1. 创建新的临时目录并 `git init`，记录绝对路径为 `$E2E_REPO`。
2. 确认 `$E2E_REPO/.partner`、项目级 `.claude/agents/partner-*` 均不存在。
3. 记录 `claude --version`、可用的 Claude model/effort 帮助，以及 Codex `model/list` 摘要。
4. 不删除用户现有全局配置；若本机已有 Partner 安装，使用安装器的可恢复 backup 机制并在报告中标记这是 reinstall，不得假称首次文件落盘。

### 1. Codex 宿主：从安装到第一次接力

在一个全新的 Codex session、`cwd=$E2E_REPO` 中，用户只发送：

```text
请从 https://github.com/LearnPrompt/partner-skill/tree/feat/v1.5-dual-host 安装搭子.skill。把我当成第一次使用的小白；安装完成后告诉我下一句只要说什么，不要让我手敲配置命令。
```

激活 skill 后用户发送：

```text
搭子，配置
```

Codex 侧必须满足：

- 打开只监听 `127.0.0.1` 的 UI，而不是连续聊天提问。
- 页面能看到 `fable / opus / sonnet / haiku` 与当前 Codex 账户模型。
- Claude effort 为本机帮助声明的值；Codex effort 跟随当前模型能力。
- 使用默认“均衡”完成预览、确认和安装。
- `.partner/config.toml` 只有 `hosts.codex` namespace，且三个角色最终 `verified=true`。
- `.partner/config.toml` 只进入 `.git/info/exclude`，不改项目 `.gitignore`。

随后用户发送 Codex 主驾的真实接力任务：

```text
搭子，在这个空仓库做一个零依赖 Python CLI：normalize_title.py 把连续空白折叠后转成 kebab-case，并写 3 个 unittest。Claude Code 先给边界条件和验收标准，Codex 实现并跑测试，再复用同一个 Claude Code session 做最终 review。最后给我 Partner Session Receipt。
```

PASS 需要同时看到：Claude 规划证据、Codex 文件 diff、测试绿灯、同一 Claude session 的最终 review，以及合法 receipt。只由一个 Agent 完成全程即 FAIL。

### 2. Claude Code 宿主：增量配置与反向接力

保持同一个 `$E2E_REPO`，启动一个全新的 Claude Code session。用户只发送：

```text
请从 https://github.com/LearnPrompt/partner-skill/tree/feat/v1.5-dual-host 安装搭子.skill。这里已经由 Codex 配过一次；请保留它的配置，把我当成第一次使用 Claude Code 这一侧的小白。
```

激活 skill 后用户发送：

```text
搭子，配置
```

Claude Code 侧必须满足：

- UI 显示已有 Codex 配置，并只新增 `hosts.claude_code`。
- apply 前后的 `hosts.codex` 原始字节一致。
- 只生成 namespaced `partner-*` agent，不覆盖用户 agent。
- 两个 namespace 的三个角色都能由 `--status` 读取；本宿主自动 smoke 后均为 `verified=true`。

随后用户发送 Claude 主驾的反向接力任务：

```text
搭子，分工给 Codex：给 normalize_title.py 增加可选的 --separator 参数并补测试。你负责计划和最终全量验收，机械实现交给配置里的 Codex fast_worker 后台任务；做完给我 Partner Session Receipt。
```

PASS 需要同时看到：Claude 的计划与分工、`delegate-codex.sh` jobId、Codex 后台实现、Claude 对完整 diff 和测试的验收、`direction: claude-driven` 且 `codex_jobs >= 1` 的合法 receipt。Claude 自己直接完成机械实现即 FAIL。

### 3. 最终证据表

新 session 必须按下面格式收口：

```text
install_from_feature_branch: PASS | FAIL
codex_setup_ui: PASS | FAIL
codex_namespace_verified: PASS | FAIL
codex_to_claude_relay: PASS | FAIL
claude_incremental_setup: PASS | FAIL
peer_namespace_byte_preserved: PASS | FAIL
claude_namespace_verified: PASS | FAIL
claude_to_codex_relay: PASS | FAIL
receipts_validated: PASS | FAIL
tests: <commands + counts>
artifacts: <E2E_REPO, config, jobs, receipts>
verdict: PASS | FAIL
blocking_reason: <none 或具体证据>
```

任意一项 FAIL，整体验收即 FAIL。不得因为配置 smoke 通过而跳过两次真实接力任务。

## 清理边界

- 验收报告确认前保留 `$E2E_REPO`、`.partner/jobs/`、receipts 和安装器 backup。
- 清理临时仓库、backup 或旧安装属于单独的破坏性步骤，必须等用户明确授权。
- 本验收只 push feature branch；不 merge、不发版。
