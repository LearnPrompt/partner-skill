# Partner 2.0

Partner 2.0 turns the original Claude Code ↔ Codex relay into a configurable, dual-host development protocol with inspectable identities, safe setup, independent judgment, and evidence-backed delivery.

## Highlights

- **[One local setup page](../../references/setup.md).** “搭子，配置” opens a localhost-only UI with concrete CLI, model, and reasoning-effort choices, exact preview, explicit confirmation, atomic apply, and post-write smoke tests.
- **Three cross-vendor identities.** Configure `deep_reasoner`, `fast_worker`, and blind `arbiter` roles independently across Claude Code and Codex.
- **Two real host adapters.** Codex-driven and Claude-driven workflows share the same `.partner/config.toml`, Goal/Loop facts, acceptance gates, and Session Receipt.
- **[Plan → Goal → PR → Verification](../../references/goal-to-pr.md).** Long work gets binary `done_when` conditions, bounded retries, maker/checker separation, and clear hard stops for merge and production.
- **[Receipt schema v2](../receipt-schema.json).** Delivery records host, scope, config source, identities used through the `roles_used` field, session reuse, jobs, checks, anomalies, and monitoring level.
- **Safer CLI boundaries.** Partner uses a compatible Codex binary, closes delegated stdin, supports non-Git targets, and strips nested Claude Code environment markers before spawning Claude CLI so first-party OAuth remains usable.

## Honest limits

- A configuration smoke test proves that each selected identity starts successfully; it does not replace a real task round trip.
- Claude Code planning can still hit stream-idle or subagent watchdog limits. Partner reports that separately from authentication failures and keeps `/cost` evidence when available.
- Tagging this release does not merge the release branch or deploy any downstream project.
